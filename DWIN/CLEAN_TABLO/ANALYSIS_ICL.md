# Анализ: ваш рабочий экран vs моя сборка

Сравнение: `CLEAN_TABLO/DWIN_SET` (ваш, работает) и старая AI-сборка (`23.icl` + T5LCFG=23).

## Главная ошибка (да, про ICL + CFG)

| | **Вы (ок)** | **Я (ошибка)** |
|--|-------------|----------------|
| Файл фона | **`32.icl`** | **`23.icl`** |
| `T5LCFG.CFG` байт `[8]` | **`0x20` = слот 32** | **`0x17` = слот 23** |
| Страницы в ICL | только **0, 1, 2, 3, 10** | 0…10, причём **4–9 = копии стр. 0** |
| Качество JPEG | ~97 KB / кадр (DGUS) | ~48 KB / кадр (Pillow) |

Панель берёт фоны **только из ICL, номер которого записан в `T5LCFG`**.  
Если на SD лежит обновлённый `23.icl`, а в CFG указан слот **32**, панель **игнорирует** ваш/`мой` `23.icl` и продолжает показывать старый `32.icl` — отсюда «клавиатура позади / не тот экран».

Это типичный слот фона DGUS: **`32.ICL`**, не 23.

## Что ещё отличалось у меня

1. **Лишние «фантомные» страницы 4–9** в ICL (копии главного экрана) — у вас их нет, правильно только реальные PIC.
2. **Другой шаблон `T5LCFG`** (не только ID библиотеки: другие байты baud/флагов) — риск рассинхрона с тем, что уже залито в панель.
3. В моих прошивках на SD иногда уходили **BMP** — по доке T5L для фона они не нужны (нужен ICL).
4. Touch/show у вас согласованы с полноэкранной стр. 10 и одним ArtText `6080` — это ок.

## Что у вас сделано правильно

- `T5LCFG[8] = 32` + файл **`32.icl`**
- В `32.icl` есть **id=10** (клавиатура), без мусорных 4–9
- `13TouchFile`: ЗАДАНО → `Pic_Next=10`, на стр. 10 — клавиши
- `14ShowFile`: стр. 0 без цифр, стр. 10 — VP `6080`

## Вывод

Ошибка не «магия 23.icl сама по себе», а **пара: имя ICL + байт слота в T5LCFG**.  
Моя сборка писала в слот **23**, ваш рабочий экран — в слот **32**. Пока CFG = 32, любые правки в `23.icl` на панели **не видны**.

Дальше сборку CLEAN_TABLO нужно вести как у вас: **`32.icl` + T5LCFG слот 32**, без подмены на 23.

**Важно (2026-07):** на этой панели page BMP (`00.bmp`…`17.bmp`) на SD **нужны вместе с `32.icl`**.  
Удаление BMP ломает смену фона (настройки «под» главным экраном). ICL паковать с **q=95, chroma 444**.

**Show (2026-07-23):** если в `14ShowFile.bin` пустые слоты каталога страниц указывают на `0x4000` (виджеты стр. 0), главный ArtText/progress остаётся поверх стр. 16. DGUS пишет unused → sentinel `0x4080` (`0xFF…`). `form_clean_tablo_show_pages.py` теперь так же чистит все ~4092 слота; VP 6000/6010/6090 остаются **LONG32**.
